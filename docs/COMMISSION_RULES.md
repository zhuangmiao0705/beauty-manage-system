# 独立项目提成

项目管理和套餐管理均支持“员工通用规则 / 独立比例”。基础水光可配置20%，功效水光可配置16%。单次项目在服务完成时成交，套餐在购买时成交；均在成交月份计提，核销不重复计提。

## 计算口径

独立项目不新增通用销售绩效，不叠加员工基础比例、超目标比例或普通/套盒手工费。原充值员工的充值绩效与提成保留。

- 额外付款提成 = 实际额外付款 × 成交时独立比例。
- 本金补差 = 各笔使用本金的 `max(本金 × 独立比例 − 该部分本金已计充值提成, 0)` 之和。
- 本次独立提成 = 本金补差 + 额外付款提成。
- 普通项目支付时仍优先使用赠送余额；赠送余额不参与独立提成。套餐只能使用本金余额和额外付款。
- 多员工共同完成独立单次项目时均分一笔提成，尾差归最后一位员工；普通项目原有按人计次规则不变。

| 场景                                                       | 充值员工A | 售卡员工B | 说明                               |
| ---------------------------------------------------------- | --------: | --------: | ---------------------------------- |
| A充值1000元，B用990元本金卖20%基础卡                       |     100元 |      99元 | 剩余10元本金对应1元原充值提成      |
| A充值1000元，B用1000元本金+980元额外付款卖1980元卡         |     100元 |     296元 | 本金补差100元，额外付款提成196元   |
| A充值1000元，B用1000元本金+1580元额外付款卖2580元16%功效卡 |     100元 |  312.80元 | 本金补差60元，额外付款提成252.80元 |

上表假设充值只计10%。若充值已取得超目标奖励，抵扣包含对应奖励。已计充值提成超过独立比例时，不追回充值员工提成，本次该笔本金补差为0；额外付款部分仍正常计提。

## 本金来源和锁定

使用本金按充值先后顺序分配，普通消费和普通套餐购买也会消耗同一来源。退款退回本金、撤销服务恢复本金时，同时恢复原充值来源及其剩余提成，不重新产生充值提成。

每次业务保存不可变的提成记录，包括来源、本金分配、已计充值提成、独立比例、补差、额外付款提成、员工分配和发生时间。基础提成与超目标奖励按业务发生时的员工配置计算：超目标奖励按当月通用绩效在该笔业务前后的差额计入。修改员工比例、目标、项目比例、套餐比例只影响后续销售提成，不重算已保存销售记录。底薪、餐补、全勤及通用手工费仍使用现有工资规则。

金额精确到分，提成采用对称四舍五入。部分本金按原充值提成比例分摊，最后一笔使用剩余提成，避免分摊累积尾差。

SQLite迁移21会按升级时系统可计算的薪酬配置固化原有销售提成，旧项目、旧购买记录保持“通用规则”，不会因后来给套餐设置独立比例而变成独立销售。历史未记录的实际发薪、人工调整无法反推；上线前应核对相关历史工资。找不到充值来源的历史本金不会被当作“从未计提”，新的独立余额购买会提示核对来源并回滚本次业务。

## 次数、有效期、赠送权益

次数卡可同时配置有效天数；0表示不限期。次数耗尽、到期、退款任一条件成立即不可再核销。时间卡仍保持有效期内不限次数。有效期按开卡时间加配置天数计算，期限和次数在购买记录中保存。

套餐可关联一个赠送套餐并设置赠送次数。成交时生成一条价格0、独立比例0的子权益记录，与主卡分开核销、分别扣减库存，继承主卡有效期，不递归赠送。主卡退款关闭未使用赠送权益；赠送卡不能单独退款。主卡或赠送卡有未完成预约时，须先处理预约。

## 退款和撤销

沿用原有退款金额规则：实际套餐价减去已用次数乘单次原价，按原支付比例退回本金和现金。独立提成按 `原已计独立提成 × 实际退款金额 / 原套餐价` 在退款月份冲回，冲回归原售卡员工，不改动其历史月份。原充值提成保留在恢复的本金来源中；之后账户退款继续走原有账户退款绩效冲减流程。

独立单次服务撤销时，在撤销月份全额冲回原独立提成，并恢复本金、赠送余额与库存。重复退款、重复撤销及重复同步不重复生成提成。

## 工资和验证

工资页面分别显示通用提成（含手工）、独立项目提成和提成合计；点击独立项目提成可查看支付拆分、已计充值提成、补差与本人分配。套餐购买窗口向店长显示预计提成，保存时桌面后端重新计算；普通员工快照不返回提成台账。

- `npm test`：浏览器仓库、提成计算与工资汇总业务测试。
- `cargo test --manifest-path src-tauri/Cargo.toml --lib --no-default-features`：SQLite迁移、真实购买/退款事务、提成计算与原有规则测试。
- `npm run build`：Vue类型检查和前端构建。

功效半年卡、年卡的功效服务次数尚未给定，需在套餐配置中填写；系统不自动猜测次数，也不自动写入门店商品数据。
